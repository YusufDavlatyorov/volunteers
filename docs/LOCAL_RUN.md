# Как запустить KhayrKhoh на своём Mac

Инструкция для человека без опыта программирования. Всё делается в программе **Терминал**:
вы копируете команду, вставляете её (⌘V) и нажимаете **Enter**.

---

## Самое короткое (если уже всё делали раньше)

```bash
cd ~/Desktop/volunteers
source .venv/bin/activate
python manage.py runserver
```

Затем откройте в браузере **http://127.0.0.1:8000/**. Чтобы остановить сайт, нажмите в Терминале
**Control + C**.

---

## Важно: Docker на Mac не нужен

В проекте есть файл `docker-compose.yml`, но он сделан **для сервера** khayrkhoh.tj, а не для Mac.
Локально он не запустится — и это нормально:

- на сервере сайт подключается к уже существующей там базе PostgreSQL. На Mac этой базы нет, и
  Docker выдаст ошибку вида `network shared_postgres_net declared as external, but could not be found`;
- контейнер `telegram_bot` запустил бы **второй экземпляр настоящего бота** с тем же токеном. Он
  начал бы перехватывать сообщения реальных пользователей у бота на сервере.

На Mac сайт запускается проще, без контейнеров:

- база данных — один файл `Gen_connect.sqlite3` в папке проекта;
- письма и сообщения не уходят наружу (о безопасности — в разделе «Безопасность: в .env нет настоящих ключей»);
- Redis и Celery заменяются встроенными упрощёнными вариантами — их ставить не нужно.

Поэтому разделы о запуске «всех контейнеров» здесь заменены одной командой запуска сайта.
Docker Desktop можно не устанавливать, а если он уже есть — не запускать для этого проекта.

---

## Безопасность: в `.env` нет настоящих ключей

С 2026-10-03 в файле `.env` на Mac **пустые** строки `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_HOST`,
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_COMMUNITY_BOT_TOKEN`. Настоящие пароль почты и токены ботов есть
только на сервере. Поэтому локальный сайт:

- не отправляет настоящих писем — он просто печатает их в Терминал (так их удобно смотреть);
- не отправляет сообщений в Telegram и не мешает настоящему боту.

Раньше для этого нужно было каждый раз вводить команду `export …` — теперь она не нужна.

Копия прежнего `.env` (с настоящими ключами) лежит в `~/khayrkhoh-backups/env-backup-2026-10-03`
(доступ только у вашей учётной записи Mac). Не копируйте её обратно в проект.

Если кто-то впишет в `.env` ключ почты или токен бота, при каждом запуске в Терминале появится
рамка из восклицательных знаков `WARNING / ВНИМАНИЕ … delivery keys in .env` со списком таких строк
(сами значения не печатаются). Если это не токен **тестового** бота (docs/TEST_BOT.md) — очистите
эти строки в `.env` (оставьте после `=` пусто) и перезапустите сайт.

## 1. Что должно быть установлено заранее

| Что | Зачем | Как проверить |
|---|---|---|
| **Python 3.14** | на нём работает сайт | в Терминале: `python3 --version` → должно быть `Python 3.14.x` |
| **Папка проекта** `~/Desktop/volunteers` | сам сайт | в Finder на Рабочем столе есть папка `volunteers` |
| **Папка `.venv` внутри проекта** | все библиотеки сайта (Django и др.) уже установлены туда | команда `ls ~/Desktop/volunteers/.venv/bin/python` печатает путь, а не «No such file» |
| **Файл `.env` внутри проекта** | настройки сайта | команда `ls -a ~/Desktop/volunteers/.env` печатает путь |

Сейчас на вашем Mac всё это уже есть. Папка `.venv` и файл `.env` скрытые (имя начинается с
точки), поэтому в Finder их не видно — это нормально.

Если `python3 --version` пишет `command not found`, скачайте Python 3.14 с
https://www.python.org/downloads/macos/ и установите как обычную программу. Если пропала папка
`.venv`, см. раздел 8, ошибка «Папки .venv нет».

## 2. Открыть Терминал и перейти в папку проекта

1. Нажмите **⌘ + Пробел**, напечатайте `Терминал` (или `Terminal`) и нажмите Enter.
2. Вставьте команду и нажмите Enter:

   ```bash
   cd ~/Desktop/volunteers
   ```

   `cd` значит «перейти в папку». Если всё хорошо, Терминал ничего не напишет — просто появится
   новая строка.

3. Проверка, что вы в нужной папке:

   ```bash
   ls manage.py
   ```

   Должно напечатать `manage.py`. Если пишет `No such file or directory`, повторите пункт 2.

## 3. Команды по порядку

Выполняйте в **том же окне** Терминала, одну за другой.

### 3.1. Включить окружение проекта

```bash
source .venv/bin/activate
```

**Что делает:** подключает библиотеки проекта (Django и остальные), установленные в папку `.venv`.
Без этого шага сайт не запустится — см. раздел 7.

**Что увидите:** в начале строки Терминала появится `(.venv)`. Проверка:

```bash
python --version
```

→ `Python 3.14.6` (последняя цифра может отличаться).

### 3.2. Миграции (подготовка базы данных)

```bash
python manage.py migrate
```

**Что делает:** создаёт или обновляет таблицы в файле базы `Gen_connect.sqlite3`, чтобы они
соответствовали текущему коду. Повторный запуск безопасен.

**Что увидите:**
- в первый раз или после обновления кода — список строк `Applying myapp.0023_community... OK`;
- если всё уже готово — `No migrations to apply.`

Обе картинки — это успех.

### 3.3. Демо-данные

```bash
python manage.py seed_demo
```

**Что делает:** создаёт демо-пользователей всех ролей, запросы о помощи, акции, отзывы, чаты,
пожертвования вещами и объявления о животных. Если демо-данные уже есть, команда их обновляет, а
не дублирует. Повторять можно сколько угодно.

**Что увидите** (через несколько секунд) — в конце три строки:

```
Demo data ready.
Users: … | Events: … | Requests: … | …
Demo password for all demo users: Volunteer2026!
```

Затем:

```bash
python manage.py backfill_achievements
```

**Что делает:** выдаёт волонтёрам значки (достижения), которые они уже заработали по демо-данным.
Уведомлений никому не шлёт. Повторный запуск безопасен.

**Что увидите:** строку вида `awarded 12 badge(s) to 5 volunteer(s)` и под ней список значков.
При повторном запуске будет `awarded 0 badge(s) to 0 volunteer(s)` — значки уже выданы, всё в
порядке.

Шаги 3.2–3.3 нужны в первый раз и после обновления кода. Для обычного запуска их можно
пропускать.

### 3.4. Запустить сайт

```bash
python manage.py runserver
```

**Что делает:** запускает сайт на вашем Mac.

**Что увидите** через пару секунд:

```
System check identified no issues (0 silenced).
October 03, 2026 - 15:00:00
Django version 5.2, using settings 'server.settings'
Starting development server at http://127.0.0.1:8000/
Quit the server with CONTROL-C.
```

**Не закрывайте это окно Терминала**, пока пользуетесь сайтом — закроете окно, остановится и сайт.
Пока вы ходите по страницам, в окне появляются строки вида `"GET /profile/ HTTP/1.1" 200` — это
нормально.

### 3.5. Проверить, что всё работает

Контейнеров здесь нет — вместо проверки контейнеров откройте в браузере:

**http://127.0.0.1:8000/health/ready/**

Если всё хорошо, на странице будет текст, начинающийся с `{"status": "ready"`. Если написано
`"not ready"`, скопируйте этот текст мне.

### Вариант: живой чат без задержки (по желанию)

С `runserver` всё работает, кроме одного: «живые» обновления (новое сообщение в чате, уведомление,
перемещение волонтёра на карте) приходят **раз в 30 секунд**, а не мгновенно. В консоли
разработчика браузера при этом видны ошибки подключения WebSocket — так и должно быть, сайт сам
переходит на запасной режим.

Чтобы проверить мгновенные обновления, вместо шага 3.4 запустите:

```bash
uvicorn server.asgi:application --port 8000
```

Увидите `Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)`. Адрес тот же. Минус:
после изменения кода этот вариант нужно перезапускать вручную, а `runserver` перезапускается сам.

## 4. Какой адрес открыть в браузере

**http://127.0.0.1:8000/**

Откроется главная страница. Кнопка «Войти» — вверху, или сразу по адресу
http://127.0.0.1:8000/login/.

Адрес `http://localhost:8000/` тоже работает. Пишите именно `http://`, а не `https://` —
локальный сайт работает без шифрования.

## 6. Как остановить и как запустить снова

**Остановить:**
1. В окне Терминала, где запущен сайт, нажмите **Control + C** (именно Control, не ⌘).
   Появится обычная строка ввода — сайт остановлен.
2. Можно закрыть окно Терминала.

Данные не пропадают: всё, что вы создали на сайте, хранится в файле `Gen_connect.sqlite3` и
будет на месте в следующий раз.

**Запустить в следующий раз** (новое окно Терминала):

```bash
cd ~/Desktop/volunteers
source .venv/bin/activate
python manage.py runserver
```

Если я обновил код (новый этап), перед последней строкой выполните ещё:

```bash
python manage.py migrate
python manage.py seed_demo
python manage.py backfill_achievements
```

## 7. Почему не работает `python3 manage.py runserver`

**Так запускать можно и нужно** — это обычный способ локального запуска. Не работает он почти
всегда по одной из трёх причин.

**1. Не включено окружение проекта (самая частая).** Ошибка:

```
ModuleNotFoundError: No module named 'django'
```

`python3` без шага 3.1 — это «голый» Python на Mac, в нём нет Django и других библиотек
проекта. Они лежат в папке `.venv`.
Решение: сначала `source .venv/bin/activate` (появится `(.venv)`), затем
`python manage.py runserver`.

**2. Терминал не в той папке.** Ошибка:

```
can't open file '/Users/<имя>/manage.py': [Errno 2] No such file or directory
```

Решение: `cd ~/Desktop/volunteers`, затем повторить.

**3. Порт 8000 уже занят** — например, сайт уже запущен в другом окне Терминала. Ошибка:

```
Error: That port is already in use.
```

Решение — в разделе 8.

Если окружение включено, то `python` и `python3` — одно и то же, подойдёт любая из двух команд.

## 8. Частые ошибки и что делать

| Что видите | Почему | Что делать |
|---|---|---|
| `ModuleNotFoundError: No module named 'django'` | не включено окружение | `source .venv/bin/activate`, затем снова команду |
| `can't open file … manage.py` | Терминал не в папке проекта | `cd ~/Desktop/volunteers` |
| `Error: That port is already in use.` | сайт уже запущен в другом окне, или порт занят другой программой | найдите другое окно Терминала с сайтом и нажмите там Control + C. Не нашли — выполните `lsof -i :8000`: в колонке PID будет число, например 12345, тогда `kill 12345`. Или запустите на другом порту: `python manage.py runserver 8001` и откройте http://127.0.0.1:8001/ |
| `ImproperlyConfigured: DJANGO_SECRET_KEY …` | нет файла `.env` в папке проекта | проверьте `ls -a .env`; если файла нет — напишите мне, не создавайте его наугад |
| `no such table: …` или `OperationalError` на странице | не выполнены миграции | остановите сайт (Control + C), выполните `python manage.py migrate`, запустите снова |
| «Неверный логин или пароль» для демо-аккаунта | нет демо-данных или опечатка в пароле | `python manage.py seed_demo`; пароль `Volunteer2026!` |
| «Слишком много попыток входа» | сработала защита от подбора пароля | остановите сайт и запустите снова — локально этот счётчик сбрасывается при перезапуске |
| Страница без оформления (просто чёрный текст) | в `.env` выключен режим разработки | в `.env` должно быть `DJANGO_DEBUG=True`; если там другое — напишите мне |
| Браузер пишет «Не удаётся установить соединение» | сайт не запущен или окно Терминала закрыто | выполните «Запустить в следующий раз» из раздела 6 |
| Браузер сам меняет адрес на `https://` и не открывает | браузер запомнил https для этого адреса | наберите адрес вручную с `http://`, или откройте http://localhost:8000/ |
| `command not found: python` | не включено окружение | `source .venv/bin/activate`, или пишите `python3` |
| Папки `.venv` нет (`No such file or directory: .venv/bin/activate`) | окружение удалено | один раз выполните `python3 -m venv .venv`, затем `source .venv/bin/activate`, затем `pip install -r requirements.txt` (несколько минут, нужен интернет) |
| `Cannot connect to the Docker daemon` или `network shared_postgres_net … could not be found` | вы запустили `docker compose …` | для Mac Docker не нужен — см. раздел «Важно: Docker на Mac не нужен». Пользуйтесь командами из раздела 3 |
| В консоли браузера ошибки `WebSocket connection … failed` | `runserver` не поддерживает WebSocket | это нормально, сайт переходит на обновление раз в 30 секунд. Для мгновенных обновлений — вариант с `uvicorn` из раздела 3 |

**Чего не делать на Mac:**
- не вписывать в `.env` токены **настоящих** ботов и не запускать с ними `run_telegram_bot` /
  `run_community_bot` — локальная копия начнёт отвечать реальным людям вместо сервера. Бота
  проверяем только с отдельным тестовым ботом — docs/TEST_BOT.md;
- не выполнять `seed_demo` на сервере — только на Mac.

Если ошибки нет в таблице — скопируйте последние 20–30 строк из Терминала и пришлите мне.
